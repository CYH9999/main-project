# اختبارات تبارك جيم

```
npm install
npm test                 # كل المجموعات
node tests/run.js المال  # مجموعة واحدة (بحث بجزء من الاسم)
TG_JSON=out.json npm test  # حفظ النتائج بصيغة JSON
```

الاختبارات تفتح الملف في متصفح حقيقي (Chromium عبر Playwright) وتعمل فوق
`window.TG` وحده — لا فوق تفاصيل الواجهة. لكل مجموعة سياق تخزين نظيف، فلا
تتسرّب بيانات مجموعة إلى أخرى.

المسار التنفيذي للمتصفح يُقرأ من `TG_CHROME` إن اختلف عن الافتراضي
(`/opt/pw-browsers/chromium-1194/chrome-linux/chrome`).

## المجموعات

| المجموعة | ما تثبته |
|---|---|
| ثوابت المال | كل دفعة تُنشئ سطر إيراد واحداً، المقبوض ≤ المستحق، الطباعة لا تصنع مالاً، حذف الدفعة يُبطل وصلها، المتوقّع في الدرج = الافتتاحي + الداخل − الخارج، والمصروف غير النقدي لا يُخصم منه |
| ثوابت المخزون | الرصيد = مجموع الحركات، لا رصيد سالب، وإلغاء الفاتورة يعيد الكمية |
| ثوابت الاشتراك | النهاية = النهاية الأصلية + أيام الأحداث، بعد الإنشاء والتجميد والتمديد والتعديل وإلغاء الحدث |
| الترقية v3/v4/v5/v6 ⇐ v7 | الترقية على نسخة مستعادة من إصدار أقدم لا تغيّر مبلغاً ولا تحرّك نهاية اشتراك، وتشغيلها مرتين يعطي النتيجة نفسها. وv7 تحديداً: كل حركة رأس مال تحمل طريقة (والقديمة «غير معروفة» لا مخمَّنة)، وتوزيع الشهر الواحد يُفصَّل بالضبط، والممتدّ القديم لا يُخترع له تفصيل |
| نموذج الحصص | القالب يولّد مواعيد، والحضور يحمل معرّف الموعد ويُعلّم الحجز، ولا التحاق ثابت بقي |
| العملة والجداول | العملة تُقفل بعد أول حركة مالية، وتغيير تسمية طريقة الدفع لا يمسّ سجلاً |
| البيانات التجريبية | تُحمَّل وتُحذف بالكامل من كل الجداول |
| الاستمرارية | الكتابة تنجو من إعادة التحميل (ومعها الملاحظات والتوزيعات والفترات المقفلة والشاشة الافتتاحية)، والنظام يقلع على التخزين المحلي ثم على الذاكرة مع تحذيرها |
| النماذج والشاشات المنبثقة | نماذج الاشتراك والمصروف والقبض وسجل الدفعات وشاشة الفاتورة |
| رسم كل الشاشات | كل شاشة وكل تبويب مالي وكل قسم إعدادات يُرسم بلا خطأ في الـ console |
| مسار الاستقبال الكامل | مشتركة ⇐ اشتراك بدفعة جزئية ⇐ وصل ⇐ قبض الباقي ⇐ إعادة طباعة ⇐ تجميد ⇐ حضور ⇐ بيع ⇐ إقفال الصندوق |
| حفظ وطباعة وصل | الطباعة لا تصنع مالاً، ومنع نافذتها لا يُفقد الدفعة ولا يُنشئ دفعة ثانية، وإعادة المحاولة تعطي الوصل نفسه |
| الاستقبال السريع | الكود + Enter (بالحرف وبالأرقام وبالأرقام العربية)، إنهاء التجميد اليوم واحتساب ما مضى وحده، وافتراضات التجديد وعدم مساس السجل القديم |
| ملاحظات الفريق | الحفظ بالكاتبة والتاريخ، رفض الفارغة وبلا مشتركة، التثبيت والتعديل والحذف |
| الفترات وتوزيعات الشركاء | لا توزيع قبل الإقفال، الربح يُثبَّت بالإقفال، التوزيع يقلّل السيولة ولا يقلّل الربح ولا يظهر مصروفاً، وكشف الشريكة |
| طرق رأس المال | النقد يدخل الدرج والتحويل والبطاقة لا، والاسترجاع ليس مصروفاً، والضخّ ليس إيراداً، وما لا تُعرف طريقته يُعزَل ويُصحَّح بفعل مسجَّل |
| دورة الشراء من المورّد | المستند وسطوره وترحيله: بضاعة تدخل، ومصروف واحد لا اثنان، وتسديد جزئي ومتبقٍّ، ومتوسط تكلفة مرجّح، وإلغاء يعكس الأثر ولا يمحو التاريخ، وكشف مورّد يجيب الأسئلة الثلاثة |
| تفصيل توزيعات الشركاء | مجموع الأشهر = المبلغ بالضبط، والتفصيل الصريح يُحفظ كما كُتب، والتعديل والإلغاء يُطابقان، والقديم بلا تفصيل يُقال عنه ذلك ولا يُخمَّن |
| الإقفال المُعان | المانع يمنع والتنبيه يُقَرّ ويُحفظ، والملخّص يقول ما يُقفَل عليه، وبعد الإقفال لا حركة إلا بتصحيح مُعلَّل مسجَّل |
| سلامة بيانات دورة الشراء | يتامى الشراء والتوزيع تُكسَر عمداً فيراها الفحص، والإصلاح يُغلق ثابت التفصيل ولا يحذف مستنداً صامتاً |
| الحصص المشمولة | المنح مع الاشتراك، الاستهلاك، إسقاطها بأرشفته كحدث ظاهر، وإعادتها بالاسترجاع |
| البحث العام | ثلاث نتائج للمجموعة، المشتركات أولاً، القفز بالكود ورقم الوصل، أفعال الصف، والتطبيع العربي |
| الشاشة الافتتاحية | الافتراضي والحفظ |
| المسار الحرج الكامل للمرحلة الأولى | الواحدة والثلاثون خطوة كاملة من إنشاء المشتركة إلى طباعة كشف الشريكة |
| المسار الحرج الكامل للمرحلة الثانية | ثلاثون خطوة: مشتركة ⇐ شراء من مورّد ⇐ رأس مال ⇐ إقفال ⇐ توزيع مفصَّل ⇐ نسخة ⇐ إعادة تحميل ⇐ استعادة ⇐ فحص سلامة، كل رقم مقارَن بلقطته |
| مساحة اللمس | لا زر تحت 32 بكسل على شاشة لمس، والمكتب لا يتغيّر |
| الهوية البصرية المتحرّكة | دورة حياة الشعار واللافتة ثابتَين ومتحرّكَين: رفع وعرض وإعادة تحميل ونسخة واستعادة واستبدال وإزالة، والكبير والنوع غير المدعوم يُرفضان، والطباعة تأخذ الإطار الثابت دائماً، والوسائط المكسورة لا تكسر الصفحة |
| الهوية المتحرّكة في الشاشة | الرفع من حقل الملف الحقيقي، والمعاينة تقول متحرّكة/ثابتة وحجماً وأبعاداً، وإعادة التحميل مرّتين لا تُنمّي الوسائط ولا النسخة |
| تشغيل الحركة الفعلي | إثباتٌ بمقارنة الإطارات لا بالوصف: لقطات متتابعة للعنصر نفسه في الأوضاع الثلاثة × جهازين (بتفضيل تقليل الحركة وبدونه)، مع ضبط مرجعي يثبت أن الملف يتحرّك في هذا المتصفح أصلاً، والطباعة ثابتة في كل وضع، والحركة تنجو من إعادة التحميل والاستعادة |
| تقليل الحركة | في سياقَي متصفح حقيقيَّين: التفضيل يجعل اللافتة والشعار ثابتين، وغيابه يُبقي الحركة، والطباعة ثابتة في الحالتين |
| التقييم الأولي عند التسجيل | السيناريوهان: تسجيل سريع بلا قياس ثم قياس لاحق، وتسجيل بقياسات أولية تدخل السجل نفسه — بلا قراءة مكرّرة، والخطأ يُكشف قبل إنشاء المشتركة |
| أثر الهوية المتحرّكة على الأداء | الرفع والإقلاع واللوحة والاستقبال وحجم النسخة، مقيسة قبل الصورة المتحرّكة وبعدها |
| النسخ الاحتياطي والاستعادة | كل الجداول في النسخة (ومنها المشتريات ودفعاتها وطرق رأس المال وتفصيل التوزيعات)، والاستعادة تُرجع السيولة والمتبقّي للموردين كما كانا، وإعادة التهيئة تفرّغ الجديد أيضاً |
| التقارير والتصديرات | بناء التقرير، فصل القيمة عن المقبوض، ومطابقته لسطور الإيراد |
