## 2. المصدر واحد

الواجهة ملفّ واحد في جذر المستودع: `tabarak-gym 3.0.html`.
هو ما يُفتح في المتصفح، وهو نفسه ما يُغلِّفه التطبيق المكتبي.

Tauri يحتاج مجلّداً فيه `index.html`، فيُنسخ الملف الواحد إليه عند البناء:

```
tabarak-gym 3.0.html  ──(scripts/prepare-frontend.mjs)──▶  app/index.html
```

`app/` **مخرج بناء** مستثنى من git، لا مصدر ثانٍ. ولا يُصان هذا بالوعد:
في مجموعة الاختبارات فحصٌ يقارن البايتات ويسقط إن تفرّق الملفان:

```
✓ واجهة سطح المكتب هي ملف المتصفح نفسه بايتاً ببايت
```

فلا `index-desktop.html`، ولا لوحة تحكّم ثانية، ولا منطق عمل مكرَّر.

## 3. البناء الرسمي: من GitHub

مثبّت ويندوز لا يُبنى إلا على ويندوز — NSIS وWiX وأيقونة الملف التنفيذي
أدواتُ ويندوز. فالطريق المُعاد إنتاجه هو:

`.github/workflows/windows-desktop.yml` → شغّليه من تبويب **Actions**
(`workflow_dispatch`)، ثم نزّلي النتيجة من **Artifacts**:

```
tabarak-gym-windows-installer
  ├── تبارك جيم_7.6.0_x64-setup.exe     207.1 ميغابايت
  └── تبارك جيم_7.6.0_x64_ar-SA.msi     205.2 ميغابايت
```

يطبع البناء حجم كل مخرَج وبصمة SHA-256 له في سجل التشغيل. والبصمة تتغيّر
بين بناءين لنفس الالتزام: NSIS يضمّن أختام وقت، فالمخرَج ليس متطابق
البايتات.

> **صفحة ترميز MSI.** حزمة MSI تُبنى بثقافة **`ar-SA`** (ترميز 1256) لا
> `en-US` (ترميز 1252): الثانية لا تمثّل حرفاً عربياً واحداً، فيسقط رابط
> WiX‏ (`light.exe`) على اسم منتج عربيّ. مضبوط في
> `bundle.windows.wix.language`.

## 4. البناء محليّاً على ويندوز

### المتطلبات

1. **Node.js 20+** — <https://nodejs.org>
2. **Rust** — <https://rustup.rs>
3. **Microsoft C++ Build Tools** مع حِمل «Desktop development with C++»
4. **WebView2** — موجود أصلاً في ويندوز 11 وفي أغلب ويندوز 10 المحدَّث

### الخطوات

```bat
git clone https://github.com/CYH9999/main-project
cd main-project
npm install
npm run desktop:build:windows
```

المخرَج:

```
src-tauri\target\release\bundle\nsis\تبارك جيم_7.6.0_x64-setup.exe
```

ولحزمة MSI أيضاً:

```bat
npx tauri build --bundles nsis,msi
```

### تشغيل التطوير

```bat
npm run desktop:dev
```

## 5. الأيقونات

أيقونات ويندوز مولَّدة من علامة النظام نفسها — الدائرة الوردية والثقل
الأبيض المرسومان في الشريط الجانبي — على حقل باذنجانيّ من لوحة الهوية:

```
scripts/brand-mark.svg  ──(npm run icons)──▶  src-tauri/icons/
```

`icon.ico` يحمل سبعة مقاسات: 16 · 24 · 32 · 48 · 64 · 128 · 256.
المقاسات الصغيرة DIB غير مضغوطة (أوسع توافقاً في صدفة ويندوز) و256 بصيغة
PNG. لا أيقونة مطوّر مؤقّتة، ولا اسم Tauri في أي حقل يراه المستخدم.

لإعادة التوليد بعد تعديل العلامة:

```bash
npm run icons
```

## 5أ. هويّة البناء وسلسلة الإثبات

**الدرس الذي أوجد هذا القسم:** خرج مثبّتان يحملان «7.6.0» نفسه — أحدهما فيه
ميزات المرحلة 4.2 والآخر ليس فيه — ولا شيء على القرص يفرّق بينهما. فاختُبر
القديم ظنّاً أنه الجديد، وضاعت جولة اختبار كاملة على ويندوز. والبناء «نجح»
في الحالتين.

فالقاعدة الآن: **النجاح ليس دليلاً، والرقم ليس هويّة.**

### ما يحمله كل بناء

`src-tauri/build.rs` يخبز في الملف التنفيذي وقت الترجمة:

| | من أين |
|---|---|
| النسخة | `CARGO_PKG_VERSION` |
| بصمة الالتزام كاملة | `GITHUB_SHA` في CI، وإلا `git rev-parse HEAD` |
| البصمة المختصرة | أول سبعة منها |
| وقت البناء | ساعة النظام وقت الترجمة |
| معرّف البناء | `<مختصرة>[-dirty][-ci<رقم>]` |
| **بصمة الواجهة المغلَّفة** | `app/frontend-sha256.txt` يكتبها `prepare-frontend.mjs` |

وتُقرأ في الواجهة من `tg_env` عبر `Build` — **ولا تُكتب في الواجهة ولا
تُخمَّن**. تظهر تحت رقم الإصدار في الشريط الجانبي وفي الإعدادات:

```
الإصدار 7.6.1 · Build a1b2c3d-ci42
```

وفي المتصفح لا جسر، فلا هويّة — ولا قيمة بديلة مخترَعة.

### نهايات الأسطر — ولماذا `.gitattributes` ضروريّ

بلا سياسة صريحة يفعّل Git على ويندوز `core.autocrlf` تلقائياً فيحوّل كل
LF إلى CRLF عند السحب. فخرج الملف الواحد من سحب CI بحجمٍ آخر: **1,218,234
⟵ 1,235,531 بايت** — بايتٌ لكل سطر من 17,297 سطراً. المحتوى واحد، لكن فحص
«المصدر = المولَّد» صار مستحيلاً على ويندوز: لا بصمة تُطابق بصمة.

فـ`.gitattributes` يفرض `* text=auto eol=lf`: ما في المستودع هو ما يُسحب هو
ما يُغلَّف، بالبايت.

### البوّابات — `scripts/verify-build.mjs`

لا يُرفع مثبّت حتى تجتاز أربع بوّابات بالترتيب، وكلٌّ منها تُسقط البناء:

```bash
node scripts/verify-build.mjs source      # قبل أي بناء
node scripts/verify-build.mjs frontend    # بعد التهيئة، قبل التغليف
node scripts/verify-build.mjs binary <exe>
node scripts/verify-build.mjs installer <dir>
```

| البوّابة | ما تُثبته |
|---|---|
| `source` | الشيفرة المسحوبة تحمل **تطبيق** كل ميزة (نافذة البدء، صندوق الشعار، مركز الملفات، جسر الطباعة، اعتراض Ctrl+P، الفتح، هويّة البناء)، والأرقام متّفقة في المواضع الأربعة، والمخطّط 8 |
| `frontend` | `SHA256(المصدر) = SHA256(app/index.html)` بالبايت، والعلامات نفسها في المولَّد، والبصمة مكتوبة للملف التنفيذي |
| `binary` | الملف التنفيذي يحمل **بصمة هذه الواجهة** وبصمة هذا الالتزام ورقم النسخة |
| `installer` | مجلّد المثبّت فيه ملف واحد لا أكثر، اسمه يحمل النسخة |

ولا تُقاس ميزة بوجود تعليق أو سطر في وثيقة: كل علامة جزءٌ من التطبيق، إن
حُذف تعطّلت الميزة. (مُقاس: إسقاط اعتراض Ctrl+P أو إظهار النافذة الرئيسية
يُسقط بوّابة المصدر فوراً.)

ثم بوّابة خامسة في CI هي أصدقها: **يُثبَّت المثبّت فعلاً** (`/S /D=`) ويُقرأ
الملف التنفيذي **المثبَّت** — لا المبنيّ. فما يصل إلى المستخدمة هو ما فُحص.

### الذاكرة المؤقّتة

تُخزَّن الاعتماديات وحدها:

```yaml
path: |
  ~/.cargo/registry/index
  ~/.cargo/registry/cache
  ~/.cargo/git/db
```

`src-tauri/target` **لا يُخزَّن**. كان مخزَّناً كلّه، وفيه `target/release`
— أي الملف التنفيذي ومخرجات التغليف — فعاد بناءٌ بمثبّت بناءٍ سابق (خرجت
حزمة فيها مثبّت 7.5.0 مع 7.6.0 لهذا بالضبط). ولا يُصلح ذلك مسحُ المجلّد بعد
استعادته: ما يُستعاد يجب ألّا يكون هناك أصلاً.

### البناء النظيف — الإجراء بالضبط

```bash
rm -rf app src-tauri/target/release      # لا واجهة مولَّدة ولا ناتج بناء
git status --porcelain                   # الشجرة نظيفة؟
node scripts/verify-build.mjs source     # الميزات في المصدر
npm run prepare:frontend                 # توليد app/ من المصدر الواحد
node scripts/verify-build.mjs frontend   # البصمة مطابقة
npx tauri build --bundles nsis
node scripts/verify-build.mjs binary "src-tauri/target/release/تبارك جيم.exe"
node scripts/verify-build.mjs installer src-tauri/target/release/bundle/nsis
```

## 5ب. الجسر الأصليّ واعتمادياته

`src-tauri/src/main.rs` يكشف عشرة أوامر لا غير، و`src-tauri/src/paths.rs`
يملك بناء المسارات وتعقيم الأسماء. **لا يقبل أمرٌ واحد مساراً من الواجهة**:
تُرسل فئة من قائمة مغلقة (`csv` · `excel` · `word` · `backup` ·
`backup-auto`) واسم ملف، والباقي يُبنى في الصدأ.

| الأمر | ما يفعله |
|---|---|
| `tg_env` | مواضع الحفظ للعرض — لا لبناء مسار في الواجهة |
| `tg_save` | يكتب ملفاً في مجلّد فئته (نصّاً أو base64) |
| `tg_list_files` | يقرأ مجلّدات النظام كلّها — مصدر «ملفات تبارك جيم» |
| `tg_list_backups` | النسخ وحدها، الأحدث أولاً |
| `tg_read_backup` | يقرأ نسخةً بالاسم من مجلّدها |
| `tg_prune_backups` | يقلّم التلقائية ولا يمسّ اليدوية ولا الأحدث |
| `tg_open_file` | يفتح ملفاً من مجلّدات النظام ببرنامجه المعتاد |
| `tg_open_folder` | يفتح مجلّد فئةٍ في مستكشف ويندوز |
| `tg_ready` | تُعلنه الواجهة عند الجاهزية: تُغلق نافذة البدء وتظهر الرئيسية |
| `tg_print` | حوار طباعة ويندوز الحقيقي |

### فتح الملفات — لماذا بلا إضافة `shell`

`tg_open_file` و`tg_open_folder` لا يقبلان مساراً. الواجهة تُرسل فئةً
واسماً، و`paths::resolve_existing` تعقّم الاسم وتبني المسار وتتحقّق من
أربعة أشياء قبل أن يخرج شيء إلى النظام: أنه مكوّن واحد لا مسار، وأنه تحت
مجلّد فئته، وأن لاحقته من لواحق تلك الفئة (فلا يُفتح `exe` من مجلّد
تصدير)، وأنه ملف قائم.

والتنفيذ `std::process::Command::new("explorer.exe").arg(path)` — وسيطٌ
واحد في `argv` بلا صدفة تفسّره، فلا اقتباس يُكسر ولا أمر يُحقن. ولهذا لم
تُضَف `tauri-plugin-shell`: قائمة الصلاحيات تبقى **فارغة** كما كانت، وما
لا يُمنح لا يُساء استعماله.

### نافذة البدء

`tauri.conf.json` يحمل نافذتين: `main` مخفيّة عند الإقلاع، و`splash`
ظاهرة تعرض `splash.html` (يُنسخ من `desktop/splash.html` مع الواجهة). وهي
صفحة بلا سكربت واحد — لا قاعدة بيانات ولا منطق عمل ولا نداء إلى الجسر.

وتُكشف الرئيسية من ثلاثة طرق حتى لا تعلق نافذة البدء أبداً:
نجاح الإقلاع (`Desktop.ready`)، وفشله (تُنادى في الحالتين)، وحارسٌ زمنيّ
في `main.rs` (`SPLASH_WATCHDOG_MS`) لا يتعلّق بالواجهة أصلاً. والكشف
يقع مرّة واحدة (`REVEALED`).

### الطباعة

الطباعة على ويندوز تمرّ من `ICoreWebView2_16::ShowPrintUI` بنوع الحوار
`COREWEBVIEW2_PRINT_DIALOG_KIND_SYSTEM` — حوار النظام لا معاينة المتصفّح.
ومعه تُلتقَط `Ctrl+P` في الواجهة حين تعمل داخل Tauri وتُوجَّه إلى الطريق
نفسه، فلا يبقى في التطبيق بابٌ يصل إلى معاينة WebView2 (وهي التي تردّ
بعبارة «This app doesn't support print preview»).

وهذا يستدعي اعتماديتين على ويندوز وحدها:

```toml
[target.'cfg(windows)'.dependencies]
webview2-com = "=0.38.2"
windows-core = "=0.61.2"
```

> **مثبَّتتان بالضبط عن قصد.** Tauri/wry يستعملان هاتين النسختين. نسخةٌ
> أحدث تضع نوعين مختلفين لنفس الواجهة في شجرة واحدة، فلا يقبل المترجم
> تحويل ما يُعيده Tauri إلى ما نستورده — وهو خطأ لا يظهر إلا في بناء
> ويندوز. فعند ترقية Tauri تُقرأ نسخته من هاتين وتُطابَق هنا.

للتحقّق من شيفرة ويندوز دون جهاز ويندوز:

```bash
rustup target add x86_64-pc-windows-gnu
cargo check --manifest-path src-tauri/Cargo.toml --target x86_64-pc-windows-gnu
```

هذا **يفحص الأنواع** في مسار ويندوز — وهو ما يمسك خطأ النسختين أعلاه —
ولا يُغني عن بناء MSVC في CI ولا عن التشغيل الفعليّ.

## 7. التوقيع الرقمي

المثبّت **غير موقَّع رقميّاً**. لا توجد شهادة توقيع في هذا المستودع ولا
يجوز أن توجد: المفاتيح الخاصّة لا تُلتزم في git.

الأثر العملي: عند أول تشغيل قد يظهر **Windows SmartScreen** بتحذير
«Windows protected your PC». التجاوز: *More info* ← *Run anyway*.

لتوقيع المثبّت لاحقاً بشهادة حقيقية يُضاف إلى
`src-tauri/tauri.conf.json` تحت `bundle.windows`:

```json
"certificateThumbprint": "…",
"digestAlgorithm": "sha256",
"timestampUrl": "http://timestamp.digicert.com"
```

وتُحفظ الشهادة في أسرار المستودع (GitHub Secrets) لا في الملفات.
**لا تُوضع شهادة وهمية ولا مفتاح تجريبيّ في المستودع.**

## 8. الاختبارات

```bash
npm test                      # المجموعة كاملة: متصفح + سطح المكتب
npm test "سطح المكتب"          # مجموعات سطح المكتب وحدها
npm test "جسر سطح المكتب"      # الملفات والطباعة الأصلية
npm test "الطباعة"             # مجموعة واحدة بالاسم

cargo test --manifest-path src-tauri/Cargo.toml --bins   # قواعد المسار والتعقيم والتقليم
```

مجموعات سطح المكتب تفرض على متصفّح حقيقي **قيود وقت تشغيل Tauri الثلاثة**:
‏`window.open` تُرجع null، وسياسة أمن المحتوى المشحونة تُرسَل فعلاً، والواجهة
تُقدَّم من مجلّد البناء. انظري رأس `tests/desktop.js`.

## 9. ما لا يُلتزم في git

```
node_modules/          app/                  src-tauri/target/
package-lock.json      src-tauri/gen/        أي مفتاح أو شهادة
```

ولا تُلتزم مثبّتات WebView2 ولا مخرجات البناء. `tauri build` ينزّل ما يلزم
وقت البناء.
